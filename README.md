# Bornier

Open source EtherCAT slaves for machine tools running LinuxCNC: hardware, firmware and tooling.

- Website: [bornier.dev](https://bornier.dev)

> **Status: design phase.** Nothing here is usable yet. The base board schematic is complete
> and checked; PCB layout comes next. The firmware is a build scaffold running on a
> NUCLEO-H563ZI development board, without the EtherCAT stack yet.

## Goals

- A family of standard-compliant EtherCAT slaves for CNC retrofits: motion (step/dir, encoders, probe), digital and analog I/O, spindle control, Modbus gateway.
- Works with any EtherCAT master; developed and tested against LinuxCNC with the IgH master (`lcec`).
- Firmware builds on the LinuxCNC PC itself with a free toolchain (`arm-none-eabi-gcc`, CMake) and updates over EtherCAT (FoE).
- Hardware designed in KiCad, published in full.

Out of scope: functional safety. E-stop and STO stay hardwired.

## Architecture

```
          EtherCAT (daisy chain)
LinuxCNC PC ──► [Base board A] ──► [EtherCAT drive] ──► [Base board B] ──► ...
 (IgH master)        │ HE10 ribbon (local bus, not EtherCAT)
                     ├── I/O module 1
                     └── I/O module n
```

- **One generic base board** per EtherCAT slave. More axes come from more boards on the
  EtherCAT chain (8 axes with two boards, 12 with three).
- **Extension modules** on DIN rail, chained to the base board by HE10 ribbons: slow I/O on SPI
  chips, without an MCU. A base board and its modules form a single modular slave.

## Base board

Schematic and PCB in [`hardware/base/`](hardware/base), generated by script (see below); the PCB is
being placed.

| Block | Content |
|---|---|
| Core | Microchip LAN9253 EtherCAT slave controller (two ports, RJ45 with magnetics), STM32H523 MCU in LQFP-100 over SPI/OCTOSPI, one shared 25 MHz MEMS oscillator |
| Power | 12 V or 24 V logic supply (10.8–30 V): fuse, TVS, reverse polarity protection, bucks to 5 V and 3.3 V; USB micro-B for bench power and DFU flashing |
| Motion | 4 axes, each on a dual RJ45: drive port (differential step/dir, enable, alarm, current-limited supply output) and encoder port (RS-422, TTL or HTL, 5 V or supply voltage); fast probe input |
| Spindle | 0-10 V speed reference, PWM, enable and direction |
| Modbus | Isolated RS-485, switchable termination |
| Safety | E-stop state input (wired, not a safety function), external watchdog on the MCU reset |
| Local bus | HE10 2 × 17 connector to the extension modules: SPI, 12 chip selects, I²C, IRQ, LATCH, OE |

The STM32H523 footprint takes any STM32H5 in LQFP-100 (H523, H533, H562, H563) without a PCB
change. The board is meant to be fed by a dedicated supply in the same cabinet; the
simulation of the input stage and its limits is in [`hardware/base/sim/`](hardware/base/sim/README.md).

The board is 107.5 × 150 mm. It mounts on a DIN rail in a Phoenix Contact UM-BASIC 108 profile
(housing kit UM-BASIC-KIT-B108-L150-7035), resting on the profile walls at the top level, or
screws onto a panel through four M3 holes at the corners, one of them plated to earth the board.
A plated hole takes the Phoenix PE contact, which earths the board to the DIN rail. Every edge
connector sits on a long edge: the profile closes the short ones; the USB jack is vertical.

## Repository layout

| Directory | Contents |
|---|---|
| [`firmware/`](firmware/README.md) | C++23 firmware on the [OpSy](https://github.com/Otatiaro/OpSy) RTOS, generated STM32H563 register headers, board support for the NUCLEO-H563ZI, bring-up example and on-target tests |
| `hardware/lib/` | `kicadgen`, the Python schematic generator and checker (ERC, netlist), and the symbols, footprints and 3D models missing from the KiCad libraries, with their generators |
| `hardware/base/` | Base board: generators (`gen/`), generated KiCad project (`kicad/`), circuit simulation (`sim/`) |
| [`tools/hil/`](tools/hil/README.md) | Hardware-in-the-loop test scripts |
| `tools/udev/` | udev rules for debug probes on Linux |

The KiCad files are generated: edit the scripts in `hardware/base/gen/`, then run
`python hardware/base/gen/schematic.py`, which regenerates the schematic and runs the checks, and
`hardware/base/gen/pcb.py` with the Python shipped with KiCad, which rebuilds the PCB from it.

Building, flashing and coding rules: [CONTRIBUTING.md](CONTRIBUTING.md).
